# Wave 0 — API / OpenAPI Reconciliation

## Evidence

- The live URL tree was enumerated by `tools/inspect_api.py`: **664 operations on 450 paths** (methods refused by a view's `http_method_names` excluded). Each operation's view, `required_module`, the permission returned by `get_required_permission()` for that action, and its serializer are listed in `api_operation_inventory.json`.
- A fresh `manage.py spectacular --validate` (test settings, scratch output) reports **33 errors (4 unique) and 171 warnings**. Four views are missing from the schema: `AnalyticsLibraryViewSet` (`/report-library/`), `SearchEntriesView`, `AccessRequestView` and `RecordHistoryView`. There are also operationId collisions and a duplicate `SessionSerializer` component. The committed `Ergonx-backend/openapi-schema.yml` was last regenerated on 2026-09-25, so it predates the finance, recruitment, insights and approvals work. **v3's claim of a schema with 'zero errors/warnings' (EV-007) no longer holds.**
- Frontend adapters live in `ergonx-frontend/src/lib/api/*.ts` (22 modules) and types in `src/types/*.ts`. All calls go through the same-origin BFF `app/api/v1/[...path]/route.ts`.

## Tenant and authorization mechanism (applies to every row)

- **TCP** (`TenantContextPermission`): resolves an ACTIVE membership. `X-Institution-ID` only selects among the caller's own memberships; a mismatch returns `tenant_mismatch`, and a suspended institution returns `institution_suspended`.
- **RBAC** (`TenantRBACPermission`): checks in this order:
  1. the view's `required_module` is enabled, else `module_disabled`;
  2. the role holds the permission code;
  3. AUDITOR is read-only, except for self-service actions.
  Module disablement is checked before permission, so a permission never overrides a disabled module.
- **TQS**: `TenantModelViewSet.get_queryset()` → `Model.objects.for_institution(request.institution)`. **SCOPE**: `common.scoping` row scope (SELF / DEPARTMENT / INSTITUTION).
- 42 operations resolve to *no* permission code. Most are public or user-level auth and platform-admin endpoints, which is expected. The tenant-level exceptions are the generic `approval-requests/{id}/approve|reject|cancel` (authorised by step assignment in the service), `recruitment/candidates/{id}/scorecard` (GET; **gap**), `record-history` (checked inside the view), and `access-requests` (any member).
- 82 operations carry no `required_module`: auth, institution context, self-service, dashboards/home, notifications, search, inbox, audit. These are module-neutral by design. Dashboards and inbox filter by enabled modules internally.

- Hard DELETE is routed for several records that have no `is_active` flag: JobPosting, Candidate, Interview, Offer, ApprovalRequest, ImportJob and ExportJob. Each of these resolves to a permission code that does not exist (`job_posting.delete`, `candidate.delete`, `interview.delete`, `offer.delete`, `approval_request.delete`, `import_job.delete`, `export_job.delete`), so the request is always refused with 403. The protection is real but accidental. W2: set explicit `http_method_names` to drop DELETE (non-behavioural).
